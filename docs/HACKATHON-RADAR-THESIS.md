# HackRadar (working name) — Thesis
Saved 2026-08-23 · Next vertical after LLMDeals stabilizes

## The alpha: "worth entering", not "what exists"

Every aggregator answers *where are hackathons* (Devpost, MLH, Oppen, DevAlpha,
Eventio — 50+ platforms scraped, zero judgment). None answer the builder's
actual question:

> **Given my skills, time, and location — which of these 500 events is worth
> entering, and what's my expected value?**

## The objective stack applied

| Engine layer | Hackathon instance |
|---|---|
| Unit of value | prize USD ÷ effort-hours ÷ win probability (+ travel cost, + career/network option value) |
| Deal types | cash prizes, credits (cloud/API — links back to LLMDeals!), fast-track to funding, job interviews, conference slots |
| Usage profile | solo vs team fit, weekend vs weeklong, online vs IRL |
| Capability score | track record of winners at similar events, judge quality, sponsor seriousness (does the prize actually pay out?) |
| Detectors | 🔥 mega-opportunity (high prize + low registrant competition + credits we've priced), deadline-radar, low-competition niche match |
| Evidence | official event page + organizer history + past winner verification |
| History moat | event outcomes tracked over time → win-rate base rates → "State of Hackathons" annual report |

## Beyond hackathons (same schema, same site family)
Bounties (Gitcoin/Algora/repo.bounties), grants (ecosystem/foundation),
agent-accessible gig work. Unifying object: **money-making opportunity for an
AI-agent builder** — normalized EV, deadline, effort, evidence.

## Why agents make this better now
An agent can read `/api/v1/opportunities.json`, filter by its own skills,
and enter autonomously. The API is the distribution. Human site = trust layer;
agent API = usage growth.
